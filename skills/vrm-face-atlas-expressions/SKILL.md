# VRM 表情アトラス（目・口のテクスチャ切り替え）

生成AI（Tripo など）で作った頭は、目や口が「絵として描かれた」ほぼ平らな面になっていることが多く、
VRoid のような立体まぶた・口内前提のシェイプキーでは表情が作れません。
この Skill は **頭は1つのまま、目と口だけを別マテリアルにして、表情ごとの絵をアトラス（タイル画像）に並べ、
VRM 1.0 の TextureTransformBind（UV オフセット）で切り替える** やり方をまとめたものです。
口パク・まばたき・ウインク・感情（喜怒哀楽）＋感情中の口パクまで、VRM 1.0 標準の仕組みだけで動きます。

例：`examples/atlas_layout.jpg`（アトラス）／`examples/emotion_x_vowel_grid.jpg`（感情×母音 36 通り）／
`examples/fix_before_after.jpg`（よくある不具合の修正前後）

---

## 1. なぜこの方式か

| 方式 | 良い所 | 困る所 |
|---|---|---|
| シェイプキーだけ（VRoid 型） | 滑らか・ブレンドできる | 目や口が「絵」の頭では形を動かしても表情にならない（まつ毛の絵が裂ける・口が潰れる） |
| 表情ごとに頭を作り直して差し替え | 絵の質は高い | 生成のたびに形・トポロジーが変わる。VRM の表情として持てない（ファイル差し替えになる） |
| **アトラス切り替え（この Skill）** | 頭は1つ。表情は絵で描ける。VRM 標準の TextureTransformBind で動く。感情＋口パクも同時にできる | 切り替えは2値（中間なし）。オフセットが「足し算」になるので組み合わせ規則が要る（§5） |

シェイプキーは「少しだけ形も動かす」補助（まぶたを閉じる・口角・あご）に使い、見た目の主役は絵に任せます。

---

## 2. マテリアルの分け方

頭のメッシュを 4 マテリアルに分けます（名前は例。後の手順でこの名前を使います）。

- `face_skin` … 顔の肌（アトラスなし・普通のテクスチャ）
- `face_eyeL` / `face_eyeR` … 左右の目の周り（**左右別**にするとウインクができる）
- `face_mouth` … 口の周り

目・口のマテリアルの範囲は「一番大きく開いた/閉じた絵が収まる範囲」より少し広めにします
（驚き顔の大きな目、閉じ目のまつ毛のはみ出しを考える）。
左右は **キャラクターの左＝+X**（glTF/VRM の +X）。`blinkLeft` は X>0 側だけを閉じます。

---

## 3. アトラスのレイアウト

UV は glTF の向き（**原点が左上・v は下向き**）で考えます。基本の UV は各アトラスの「左上タイル」に収めておき、
表情はそこからのオフセットで別タイルへずらします。

**目（3×3、左右それぞれ）**

```
+---------+---------+---------+
| neutral | closed  | happy   |   offset (0,0) / (1/3,0) / (2/3,0)
| angry   | sad     |surprised|   offset (0,1/3) / (1/3,1/3) / (2/3,1/3)
| relaxed |  空き   |  空き   |   offset (0,2/3)
+---------+---------+---------+
```

**口（6×6）＝ 行が感情・列が母音**

```
列:   rest | aa | ih | ou | ee | oh       （列オフセット = 列番号 / 6）
行0 neutral / 行1 happy / 行2 angry / 行3 sad / 行4 surprised / 行5 relaxed   （行オフセット = 行番号 / 6）
```

列 0（rest）は「その感情の閉じた口」。感情は**行**のオフセット、母音は**列**のオフセットだけを持つので、
**感情＋母音 = 2つのオフセットの足し算 = ちょうど (感情, 母音) のマスに着地**します。これで「笑いながら喋る」ができます。

---

## 4. タイルの描き方・作り方（揃えるコツ）

1. **基準タイルを先に作る**：頭の元テクスチャを、目/口マテリアルの UV 範囲で切り出したものが「neutral」。
   他のタイルはこれを土台に描き換える（生成AIで描くなら neutral タイルを入力にして差分だけ描かせる）。
2. **地の肌色を顔に合わせる**：タイルの縁の肌色が顔本体とずれると、閉じ目のときに目の周りが「四角い板」に見える。
   各タイルの肌部分を顔の肌に色合わせ（領域ごとにトーンマッチ）する。
3. **まつ毛のはみ出し**：閉じ目・笑い目では、開き目のまつ毛の絵（や立体まつ毛パーツ）がはみ出して残りやすい。
   閉じる表情では開き目のまつ毛を消す／立体まつ毛パーツはシェイプキーでまぶたの下に潰す。
4. **余白（パディング）とにじみ止め**：タイルの内側に 4〜6% の余白＋外側に数十 px の色のにじみ（bleed）を入れる。
   ないとミップマップ（引きの絵）で隣のタイルの色が混ざる。`scripts/pack_atlas.py` が自動でやる。
5. **透明は使わない**：アトラスに透明部分を作ると、半開きの目が透けて奥が見える・並び順で消える等が起きる。
   **全タイル不透明（RGB）**で描き、マテリアルも OPAQUE にする。透明が要らなければアルファチャンネル自体を捨てる（軽くもなる）。
6. **タイルサイズ**：通常版は目 1024px タイル（3×3 = 3072px）、口は 4096px アトラス（1 タイル ≈683px）。
   Web 用の軽量版はその半分。

## 5. Blender + VRM Add-on での設定

`scripts/setup_face_atlas_bindings.py` が以下をまとめて行います（設定は `scripts/face_atlas_config.example.json`）。

1. 頭メッシュの目/口マテリアルの UV を左上タイルに収める（すでに収まっていれば何もしない）。
2. 4 つの顔マテリアルを MToon にして、**陰影パラメータを全部同じ値**にする（§8 の白飛び・段差対策）。
3. VRM 1.0 の表情を作る。各表情に
   - **Morph Target Bind**（補助のシェイプキー。例 `blink`, `aa`, `happy_eyes`, `happy_mouth`）
   - **Texture Transform Bind**（マテリアルとオフセット、scale は (1,1)）
   - **isBinary = true**（0.5 で切り替わる。中間の半端なオフセットを出さない）
   - 感情（happy/angry/sad/surprised/relaxed）は **overrideBlink = block**、**overrideMouth = none**
     （目は感情が持つので blink を止める／口は感情の行＋母音の列を足すので止めない）

設定例（README の表と同じ内容）：

| 表情 | Morph | Texture Transform（offset） | overrideBlink | overrideMouth |
|---|---|---|---|---|
| blink | blink | eyeL (1/3,0), eyeR (1/3,0) | none | none |
| blinkLeft / blinkRight | blinkLeft / blinkRight | eyeL または eyeR (1/3,0) | none | none |
| aa / ih / ou / ee / oh | 同名 | mouth (1/6,0) (2/6,0) (3/6,0) (4/6,0) (5/6,0) | none | none |
| happy | happy_eyes, happy_mouth | eyeL+R (2/3,0), mouth (0,1/6) | **block** | none |
| angry | angry_* | eyeL+R (0,1/3), mouth (0,2/6) | **block** | none |
| sad | sad_* | eyeL+R (1/3,1/3), mouth (0,3/6) | **block** | none |
| surprised | surprised_* | eyeL+R (2/3,1/3), mouth (0,4/6) | **block** | none |
| relaxed | relaxed_* | eyeL+R (0,2/3), mouth (0,5/6) | **block** | none |

**足し算ルール（重要）**：VRM はオフセットを足し合わせる。だから
- 同時に効かせてよいのは **母音1つ＋感情1つ** まで（母音2つ = 列が2つ分ずれて別のマスへ飛ぶ）
- 感情も同時に1つ（行が2つ分ずれる）
- blinkLeft と blinkRight の同時は OK（別マテリアルなので足し算にならない）

VRM 0.x（UniVRM）で使う場合は Material Value Bind `_MainTex_ST` = (1, 1, offsetX, −offsetY)
（Unity は UV 原点が左下）。0.x には override がないので、アプリ側で感情中の blink を止める。

## 6. 実行時のガード（three-vrm）

他社アプリのリップシンクは母音の切り替わりで 2 つを同時に少し出すことがあり、1〜2 フレーム別の口が出る。
自分のアプリでは `scripts/vrm_face_guard.js` のように **「一番強い母音だけ」「感情は1つだけ」** に絞ってから
`expressionManager` に渡す。同ファイルに「感情中は止める・ランダム間隔のまばたき」も入っている。

## 7. 検証チェックリスト（書き出すたびに）

- [ ] **全組み合わせを描画**：感情×母音（6×6）、blink / blinkLeft / blinkRight、各感情を正面・45°・315° で
      （`scripts/render_combo_check.py` → `scripts/make_grid.py`）
- [ ] **コマ送りで拡大**：切り替わりの瞬間、まつ毛のはみ出し、閉じ目の「板」、45° で奥の目がまぶたの外に出ていないか
- [ ] **ミップマップ**：サンプラーの minFilter = LINEAR_MIPMAP_LINEAR（9987）。引きの絵で隣タイルの色が出ないか
- [ ] **emissive を揃える**：Blender（VRM Add-on）の書き出しは、MToon に変換した素材で emissiveFactor = (1,1,1) と
      `KHR_materials_emissive_strength` = 0（Blender の「放射の強さ」）を一緒に書く。three.js / three-vrm は強さ 0 を掛けるので
      見た目は光らないが、強さ拡張を読まないツールでは真っ白に光る。**光らせない素材は emissiveFactor = 0 に揃える**。
      逆に**わざと光らせる素材（夜でも黒つぶれしない等）は emissiveStrength を 1 以上に**しないと、何をしても光らない
- [ ] **全マテリアル MToon・不透明**、マットキャップ未使用なら matcapFactor = (0,0,0) を明示（仕様の既定値は白）
- [ ] **lookAt の offsetFromHeadBone** が VRM の軸（x, 上, 前）で目の位置になっているか（Blender の座標のまま入れると目より下を向く）
- [ ] **サムネイル**（meta の thumbnailImage）が入っているか
- [ ] 書き出し後に **Blender で読み込み直し**＋**JSON を直接読んで**、表情の数・バインド・揺れ・当たり判定が残っているか

## 8. 軽量化（Web 用）

`scripts/slim_glb.py`（書き出し後の .vrm にかける）：
- どこからも参照されていない accessor（書き出されたが使われないシェイプキーの法線など）を削除
- シェイプキーの位置差分を **sparse accessor** に（動く頂点だけ持つ）→ 表情データが約 1/3
- スキンのウェイトを正規化 UNSIGNED_BYTE に（誤差 0.6% 未満）
- 全テクスチャにミップマップ付きサンプラー、emissive 0、matcap 0 も同時に設定
- 例：28MB → 12MB（テクスチャ半分＋上記）。読み込み直して表情・揺れが残ることを必ず確認

## 9. スタジオ（強い照明）でのつまずき

- **顔の目や口だけ四角いブロックになる**：顔の 4 マテリアルの MToon パラメータ（陰の色・shadingShift・toony・GI・rim）が
  **全部同じか**を確認。違うと、影に入ったときに目や口の範囲だけ色が変わる。
- **顔が白っぽい**：強いライトでは baseColor がそのまま飛ぶ。頭の baseColor を少し下げて暖色寄りに、陰の色も肌色寄りに（下の項目）。
  emissive の値も確認する（§7。three.js では強さ 0 なら影響しないが、他のツールでは白く光ることがある）。
- **暗い場所で真っ黒になる**（環境光の弱いアプリ）：縁の光（parametricRim）と、色の絵を使ったごく弱い自己発光
  （emissiveTexture = 色の絵、emissiveFactor 0.1 前後、**emissiveStrength 1**）が効く。
- **アプリ側の「マテリアル名で補正をかけるルール」**（例：名前に `_SKIN` が入るものだけ陰を濃くする）は、
  4 つの顔マテリアル全部に当たるか、どれにも当たらないかにする。1つだけ当たると段差が出る。
- 頭の色は暖色寄りに（baseColor を少しだけ下げて暖かく、陰の色も肌色に近く）すると、強いライトでも「肌」に見える。

## 10. 今回あったよくある失敗

1. **半開きの目が透ける**：アトラスやマテリアルに透明（BLEND/HASHED）が残っていた。→ 全部不透明・アルファ破棄。
2. **閉じ目のまわりが四角い板**：タイルの地の肌色が顔とずれていた。→ タイルごとに肌をトーンマッチ。
3. **体の肌が灰色・顔と色が違う**：体マテリアルの baseColorFactor が暗い値で、肌まで灰色に。→ 掛け算をやめてテクスチャに焼き込み（掛け算は linear 空間で）。
4. **カメラが後ろを回ると頭の向きがガクッと飛ぶ**（見つめ追従を入れたアプリ側）：角度を ±180° でクランプしていた。→ 追従量を
   smoothstep で角度に応じて減らし、真後ろ付近では 0 にする（`vrm_face_guard.js` の `lookAtWeight` 例）。
5. **顔中央の縦スジ・頬の黒い点**：UV の継ぎ目と元テクスチャの汚れ。→ 3D 上でぼかして元テクスチャを直してからタイルを作り直す。
6. **書き出しでコライダーが回る・matcap が消える**：Blender の往復で起きることがある。→ 書き出し後に JSON を見て直す。

---

## 11. やらなかったこと

- 視線（lookAt）で目を動かす：目が「肌に描かれた絵」なので回す目玉がない。アトラスをずらす方式は隣のタイルが見えるので不可。
  視線が要るなら目玉を別パーツで作る必要がある。
- 表情の中間（ブレンド）：TextureTransformBind は isBinary で使う前提。滑らかさが要る所はシェイプキー側で補う。
- VRM 0.x 版の書き出し（手順の注記だけ）。
